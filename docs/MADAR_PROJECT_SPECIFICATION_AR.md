# MADAR | مَدار
## وثيقة مواصفات المشروع
**النسخة المرجعية الأولية المعتمدة قبل مرحلة البناء**

> هذه الوثيقة هي المرجع التصميمي والتقني للمشروع. أي قرار جديد أو تغيير لاحق يجب إضافته إلى الوثيقة مع توضيح أنه تعديل، بدل تعديل النظام عشوائياً أثناء التنفيذ.

## 1. الهوية الأساسية
- اسم التطبيق: **مَدار | MADAR**
- اسم الحزمة الموحد المقترح: `app.madar.com`
- Android application ID: `com.madar.app`
- iOS Bundle ID: `com.madar.app`
- الهدف: تطبيق إسلامي عالمي واسع النطاق، فاخر وحديث، دقيق في المحتوى، يعمل Offline-first، ويجمع القرآن والحديث والعبادات والمصادر والتعليم والأدوات في منظومة واحدة.

## 2. مبادئ المشروع
- الدقة الدينية أولوية مطلقة؛ الجمال لا يتقدم على صحة المحتوى.
- لا يتم كتابة القرآن أو الحديث أو الأدعية من الذاكرة.
- كل نص أو معلومة دينية أساسية يجب أن ترتبط بمصدر ومرجع واضحين.
- النص الأصلي، التفسير، الترجمة، والشرح يجب أن تكون طبقات منفصلة وواضحة.
- عند وجود خلاف معتبر، يعرض الخلاف وينسب كل قول إلى مصدره دون تقديم رأي التطبيق على أنه حقيقة متفق عليها.
- لا توجد صلاحيات مخفية أو استخدامات غير معلنة للبيانات.
- التطبيق Offline-first ولا يعتمد على خادم خاص مدفوع.
- الهيكل يجب أن يكون قابلاً للصيانة والتوسع لسنوات.

## 3. المنصات وتقنية البناء
- Flutter + Dart كقاعدة كود مشتركة لـ Android وiOS.
- استخدام Kotlin على Android وSwift على iOS فقط عند الحاجة إلى تكامل أصلي لا يغطيه Flutter أو plugin موثوق.
- Clean Architecture + MVVM.
- تنظيم Feature-based مع فصل Core وData وPlatform.
- قاعدة بيانات محلية SQLite عبر Drift.
- إدارة الحالة: Riverpod.
- التنقل: GoRouter.
- فهرسة وبحث محلي سريع عبر SQLite FTS5 أو آلية مناسبة.
- نظام أخطاء وتسجيل مناسب، واختبارات للوحدات والمنطق والحسابات الحساسة.

## 5. نظام التصميم والهوية البصرية
- واجهة Premium حديثة، فاخرة، هادئة ومتناسقة، وليست بسيطة Minimal.
- شفافية مدروسة UI Frosted/Glass حقيقية مع Blur وطبقات إضاءة وحدود دقيقة وظلال وDepth.
- الهندسة الإسلامية جزء من لغة التصميم نفسها وليست زخرفة عشوائية.
- لا Emoji داخل واجهة التطبيق.
- ممنوع استخدام رسومات أو أيقونات بدائية أو عناصر هندسية عشوائية.
- استخدام SVG/Vector وأصول عالية الجودة وCustomPainter عند الحاجة.
- Design System مركزي للألوان والخطوط والمسافات والحواف والظلال والزجاج والأيقونات والحركات.
- دعم الوضع الداكن والفاتح والعربية RTL بشكل صحيح.
- الشعار والأيقونة يستخدمان رمزاً أساسياً واحداً: مفهوم النقطة + المدار، مع صفحتين قرآنيتين مجردتين متداخلتين، وزخرفة هندسية إسلامية دقيقة وخطوط عربية تجريدية غير مقروءة، ومدار واحد متشابك يعطي عمقاً ثلاثي الأبعاد.
- الاتجاه اللوني المقترح: أخضر زمردي عميق، ذهبي دافئ محدود، خلفيات سوداء/كحلية عميقة، ولمسات عاجية.

## 6. التنقل الرئيسي
- الرئيسية.
- القرآن.
- الحديث.
- العبادة: الصلاة، الأذكار، الأدعية، التسبيح، القبلة، والمتابعة.
- المزيد: المكتبة، الحج والعمرة، أسماء الله، التقويم، الصوت، الإعدادات وغيرها.
- البحث الشامل يكون إجراءً بارزاً في أعلى التطبيق وليس بالضرورة تبويباً سادساً في شريط التنقل.

## 7. الرئيسية
- لوحة يومية وليست Feed مختلطاً.
- هوية MADAR والبحث والتاريخ الهجري والميلادي، مع الموقع اختيارياً.
- بطاقة صلاة زجاجية رئيسية تضم الصلاة القادمة، العد التنازلي، وقت الأذان، والتاريخ الهجري والميلادي داخل نفس البطاقة.
- اختصارات للقرآن والأذكار والحديث والقبلة.
- محتوى يومي: آية، حديث، ذكر، مع المصدر.
- متابعة العبادة اليومية.
- متابعة آخر نشاط.

## 8. القرآن
- القرآن كاملاً مع قراءة وبحث وتفسير وترجمات وكلمة بكلمة عند توفر مصدر موثوق.
- قراء متعددون، تشغيل متواصل، تكرار للحفظ، تنزيلات واستخدام دون إنترنت.
- علامات مرجعية، ملاحظات، آخر موضع، أهداف يومية وختمة، مشاركة.
- إعداد فتح القرآن قابل للتخصيص: متابعة آخر قراءة، واجهة السور، آخر سورة، أو صفحة يحددها المستخدم.
- أول استخدام يفتح قائمة السور.
- ثلاثة أوضاع: مصحف، قراءة، دراسة.
- وضع المصحف ذو بيئة قراءة هادئة ومظهر مصحفي، مع خطوط وصفحات متعددة عند توفرها.
- وضع الدراسة يربط الآية بالتفسير والترجمة والمعاني والروابط المرجعية.
- Ayah Info: رقم السورة والآية، مكي/مدني عند توثقه، أسباب النزول عند ثبوتها، التفسير، الترجمات، معاني الكلمات، السياق والموضوع، الآيات والأحاديث المرتبطة عند ثبوت العلاقة.
- ممنوع إعادة صياغة النص القرآني على أنه النص الأصلي.

## 9. الحديث
- تنظيم مصدر أولاً: المجموعات، الكتب، الأبواب.
- بحث وفلاتر حسب المصدر والكتاب والباب والموضوع.
- إظهار الراوي والسند عند توفرهما.
- رقم الحديث ومرجعه.
- درجة الحديث عندما تكون موثقة، مع اسم مصدر الحكم.
- إذا اختلفت أحكام المصادر، يعرض الاختلاف منسوباً إلى مصادره.
- شرح الحديث منفصل عن النص.
- مفضلة وملحوظات ومشاركة وروابط ذكية.
- لا يتم تصحيح أو تضعيف حديث من طرف التطبيق من تلقاء نفسه.

## 10. الأذكار والأدعية
- الصباح والمساء، بعد الصلاة، النوم والاستيقاظ، الطعام، السفر، المنزل والمسجد، المرض، المطر والمناسبات.
- أدعية قرآنية ونبوية.
- تصنيفات وبحث ومفضلة وسجل.
- صوت عند توفر مصدر موثوق.
- عداد وتكرار وتقدم حسب العدد الثابت في المصدر.
- تذكيرات اختيارية.
- عمل Offline.
- زر المصدر لكل ذكر: النص، المصدر، المرجع، درجة الحديث عند انطباقها، ومعلومات التحقق.

## 11. الصلاة
- الصلوات الخمس، الشروق، قيام الليل، والعد التنازلي.
- الأذان لكل صلاة وإشعارات قبل الصلاة وإعدادات مستقلة لكل صلاة.
- طرق حساب متعددة ومذاهب/إعدادات العصر عند الحاجة.
- موقع تلقائي أو يدوي.
- تعديلات يدوية للأوقات.
- جدول يومي وأسبوعي.
- سجل صلاة اختياري.
- عمل Offline بعد الإعداد.
- Widget للصلاة.
- وصول سريع إلى أذكار ما بعد الصلاة.

## 12. القبلة
- بوصلة حقيقية واتجاه مكة مع زاوية رقمية.
- حركة سلسة وتأكيد واضح عند محاذاة القبلة.
- خريطة عند توفر البيانات.
- معايرة للبوصلة عند الحاجة.
- تعمل دون إنترنت بعد توفر الإحداثيات المطلوبة.
- تحديد تلقائي للموقع أو اختيار المدينة/الإحداثيات يدوياً.
- تنبيه عند غياب الحساسات أو ضعف موثوقية القراءة.
- تصميم إسلامي فاخر غير مزدحم.

## 13. التقويم الإسلامي
- عرض هجري وميلادي معاً.
- تقويم شهري هجري.
- تحويل هجري/ميلادي في الاتجاهين.
- المناسبات الإسلامية وفق منهجية واضحة.
- رمضان والعشر الأوائل من ذي الحجة وعرفة وعاشوراء وغيرها حسب المنهجية والمصدر.
- إظهار الاختلاف في بداية الأشهر عند الحاجة وعدم تقديم تاريخ مختلف كحقيقة وحيدة.
- عد تنازلي وتذكيرات للمناسبات.

## 14. أسماء الله الحسنى
- الأسماء مع المعنى والشرح المختصر الموثوق.
- المصدر والدليل عند الحاجة.
- بحث ومفضلة وصوت عند توفر مصدر موثوق.
- ربط بآيات وأحاديث ذات صلة عند ثبوتها.
- مشاركة منظمة مع المصدر.

## 15. التسبيح والذكر
- عداد تفاعلي، جلسات ذكر، اختيار ذكر موثوق، وعدد مستهدف.
- اهتزاز وصوت اختياريان.
- استكمال الجلسة وحفظ السجل.
- أهداف يومية وإحصاءات أسبوعية/شهرية اختيارية.
- عدم تحويل العبادة إلى نظام ألعاب أو منافسة.
- ربط بالأذكار الصحيحة ومصادرها.

## 16. الحج والعمرة
- دليل الحج والعمرة خطوة بخطوة.
- الإحرام والمواقيت وترتيب المناسك.
- الأدعية والأذكار المرتبطة بالمناسك مع المصادر.
- ما يجوز وما لا يجوز، والأخطاء الشائعة، مع مصادر موثوقة.
- خرائط ومواقع مهمة عند توفر بيانات مناسبة.
- وضع متابعة أثناء النسك.
- بحث وتنزيل للعمل Offline.

## 17. المكتبة الإسلامية
- السيرة، قصص الأنبياء، الصحابة، علوم القرآن، علوم الحديث، الفقه، العقيدة، الأخلاق والآداب، التاريخ الإسلامي، ومقالات ودروس موثوقة.
- تصنيف حسب الموضوع وبحث وحفظ للقراءة لاحقاً.
- مشاركة مع المصدر.
- ربط المحتوى بالآيات والأحاديث عند ثبوت العلاقة.
- المحتوى غير الموثق لا يدخل المحتوى الأساسي.

## 18. الصوت
- قرآن ومواد صوتية موثوقة عند توفرها.
- تشغيل بالخلفية، شاشة القفل، Bluetooth، قوائم تشغيل، تكرار، سرعة تشغيل، مؤقت إيقاف.
- تحميل وحذف المحتوى الصوتي.
- عدم وضع كل الملفات الصوتية داخل APK.

## 19. البحث الشامل والربط الذكي
- بحث واحد عبر القرآن والتفسير والحديث والأذكار والأدعية وأسماء الله والمكتبة.
- النتائج مصنفة حسب القسم مع فلاتر.
- فتح النتيجة في قسمها الأصلي.
- روابط ذكية:
  - آية → تفسير → سبب نزول عند ثبوته → حديث مرتبط → موضوع → آيات مرتبطة.
  - حديث → آيات مرتبطة → أحاديث ذات صلة → موضوع → شرح → المصدر.

## 20. متابعة العبادة
- متابعة الصلاة والقرآن والأذكار والتسبيح والهدف اليومي.
- سجل يومي وأسبوعي وشهري.
- آخر نشاط وأهداف قابلة للتخصيص.
- إحصاءات هادئة دون عناصر لعب مبالغ فيها.

## 21. قاعدة البيانات والمحتوى
- قاعدة محلية منظمة تشمل القرآن والتفسير والترجمات والحديث والأذكار والأدعية وأسماء الله والتقويم والمكتبة وبيانات الصوت.
- المحتوى منفصل عن كود التطبيق قدر الإمكان.
- حزم محتوى مستقلة قابلة للتحديث.
- Versioning وMigration لقاعدة البيانات.
- فهرسة محلية للبحث.
- كل مادة دينية تحمل بيانات مصدرها ونسخة المحتوى.
- القرآن: السورة، الآية، النص، نوع النص، المصدر، إصدار البيانات.
- الحديث: الكتاب، الباب، الرقم، النص، الراوي/السند عند توفره، درجة الحديث، ومصدر الحكم.
- التفسير: المفسر، الكتاب، الموضع.
- لا مصدر مجهول أو غير قابل للتحقق يدخل النسخة الرسمية.

## 22. Offline-first
- الوظائف الأساسية يجب أن تعمل دون اتصال.
- القرآن، المحتوى الأساسي للأذكار، أسماء الله، التقويم، البحث المحلي، وإعدادات المستخدم محلياً.
- الصلاة والقبلة تعملان بعد توفر بيانات الموقع/الإحداثيات والحساسات اللازمة.
- الصوت والمحتوى الكبير حزم اختيارية قابلة للتنزيل والحذف.
- لا يوجد اعتماد أساسي على Backend خاص.

## 23. الخصوصية والصلاحيات
- طلب الصلاحية فقط عند الحاجة وبشرح واضح للمستخدم.
- الموقع للصلاة والقبلة، مع خيار يدوي عندما يكون ممكناً.
- الإشعارات للأذان والتذكيرات والمناسبات.
- التوقيت الدقيق لا يستخدم إلا إذا احتاجته الوظيفة فعلاً وبما يتوافق مع قيود النظام.
- عدم طلب وصول شامل للتخزين دون ضرورة.
- بيانات القراءة والأهداف والإعدادات محلياً قدر الإمكان.
- مراعاة اختلاف سياسات Android وiOS.
- لا صلاحيات مخفية ولا جمع غير ضروري.

## 24. قابلية الصيانة والتوسع
- فصل كل Feature قدر الإمكان.
- عدم وضع منطق الأعمال داخل Widgets.
- عدم تكرار الكود.
- Design Tokens مركزية.
- اختبارات للمنطق والحسابات والمحتوى.
- معالجة أخطاء واضحة.
- توثيق داخلي.
- إدارة Dependencies وإصدارات قاعدة البيانات والمحتوى.
- إمكانية إضافة ميزات أو تعديل التصميم دون إعادة بناء المشروع من الصفر.
- إبقاء Android/iOS-specific code داخل طبقات المنصة.

## 26. قواعد الجودة قبل الإصدار
- مراجعة المحتوى الديني ومصادره.
- اختبار النصوص وعدم وجود أخطاء أو اقتطاعات غير مقصودة.
- اختبار البحث والروابط المرجعية.
- اختبار الحسابات ومواقيت الصلاة والقبلة والتقويم.
- اختبار الإشعارات والخلفية.
- اختبار Offline.
- اختبار أحجام الشاشات واللغات واتجاه RTL.
- اختبار Android وiOS على أجهزة فعلية عندما تتوفر.
- اختبار استعادة البيانات وترقيات قاعدة البيانات.
- قياس حجم التطبيق واستهلاك الذاكرة والبطارية قبل الإصدار.

## 27. قرارات مؤجلة
- اختيار المصادر النهائية المرخصة لكل نوع من المحتوى.
- تفاصيل ترخيص وإعادة توزيع الصوتيات والكتب والترجمات.
- قائمة Plugins النهائية لـ Android/iOS بعد اختبارها وتوافقها.
- تفاصيل Widgets لكل نظام.
- تفاصيل نظام تحديث حزم المحتوى وتوقيعها والتحقق من سلامتها.
- سياسة النشر والتوزيع سيتم تحديدها لاحقاً، ولا تدخل في مرحلة التصميم الحالية.

## 28. ملاحظة تنفيذية
هذه الوثيقة هي مرجع تصميمي وتقني للمشروع قبل البناء. أي قرار جديد أو تغيير لاحق يجب إضافته إلى الوثيقة مع توضيح أنه تعديل، بدل تعديل النظام عشوائياً أثناء التنفيذ.

- **الإصدار المرجعي الأولي:** تم إدخال هذه الوثيقة إلى مستودع المشروع لتصبح مرجعاً ثابتاً أثناء التنفيذ.
- **قاعدة تنفيذية:** لا يتم اعتبار أي Feature مكتملة بمجرد إنشاء شاشة شكلية؛ الإكمال يتطلب تنفيذ الوظيفة والتحقق منها.
- **قاعدة البناء:** GitHub Actions للبناء اليدوي فقط عبر `workflow_dispatch`، وليس مع كل Push.
