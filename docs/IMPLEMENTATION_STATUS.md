# حالة تنفيذ مَدار

## قاعدة الحالة
الشاشة أو Route لا يعني اكتمال الميزة. لا تُعلن أي ميزة مكتملة إلا بعد تنفيذ منطقها وربط بياناتها ومعالجة أخطائها واختبارها على الأجهزة المستهدفة.

## ما أُنجز في الدفعة الكبيرة
- Navigation Shell فعلي مع أقسام الرئيسية والقرآن والحديث والعبادة.
- مسار متابعة العبادة وتخزينه محلياً.
- حفظ تقدم القراءة والتسبيح والمفضلة والملاحظات عبر Drift.
- بحث محلي موحد في الجداول المتاحة.
- مواقيت الصلاة مع إدخال إحداثيات يدوي.
- أساس بوصلة القبلة باستخدام accelerometer + magnetometer مع حساب bearing إلى مكة.
- صلاحيات واضحة مع عدم طلب صلاحية runtime للحساسات.
- GitHub Actions يدوي فقط، مع مسار Android وiOS.

## ما يزال غير إنتاجي
1. Drift generation + analyze + tests يجب تشغيلها يدوياً عبر GitHub Actions.
2. البحث الحالي SQL contains وليس FTS5، ويحتاج فهرسة للمحتوى الكبير.
3. قارئ القرآن الكامل وأنماط المصحف/القراءة/الدراسة والتفسير والترجمات والروابط لم تُغلق بعد.
4. حساب الصلاة الحالي أساس رياضي ويحتاج مطابقة مع مراجع موثوقة لكل طريقة ومواقع متعددة قبل الاعتماد.
5. القبلة تحتاج معايرة حقيقية، معالجة declination، وحالات الحساس غير المتاح.
6. الموقع التلقائي يحتاج تكامل geolocator وشرح/طلب الصلاحية قبل الاستخدام.
7. الإشعارات والأذان والخلفية وإعادة التشغيل لم تُغلق بعد.
8. الصوت والتنزيلات والكاش وحقوق المحتوى لم تُغلق بعد.
9. الحزم الدينية الرسمية لم تُدمج حتى الآن، حفاظاً على شرط التوثيق والترخيص.
10. الربط الذكي وواجهات provenance والمكتبة/Hajj/Umrah تحتاج ربط بيانات حقيقي.
11. iOS يحتاج اختبار CI فعلي وApple signing قبل أي توزيع.

## سياسة المحتوى
لا توجد نصوص دينية تجريبية. كل نص رسمي يجب أن يأتي من مصدر موثق ومرخص، مع المصدر والمرجع والإصدار والتراخيص والتحقق.
