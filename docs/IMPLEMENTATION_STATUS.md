# حالة تنفيذ مَدار

## قاعدة الحالة
وجود شاشة أو Route لا يعني اكتمال الميزة. لا تُعلن الميزة مكتملة إلا بعد منطقها، بياناتها، أخطائها، وصلاحية تشغيلها على الأنظمة المستهدفة.

## الدفعة الكبيرة الحالية
- بنية Flutter + Riverpod + GoRouter + Drift قائمة.
- قاعدة بيانات محلية تشمل المحتوى الديني، المصادر، الحزم، المستخدم، الصوت والتتبع.
- Repository providers موحدة.
- حفظ المفضلة والملاحظات والتقدم والإعدادات محلياً.
- قارئ القرآن مرتبط ببيانات Drift وله أوضاع مصحف/قراءة/دراسة.
- بحث محلي موحد عبر القرآن والحديث والأذكار والأدعية وأسماء الله.
- مواقيت الصلاة لها أساس حسابي وطرق حساب متعددة.
- القبلة مرتبطة بحساسات accelerometer/magnetometer وحساب bearing إلى مكة.
- خدمة الموقع التلقائي منفصلة ويمكن تجاوزها بإحداثيات يدوية.
- التقويم الهجري/الميلادي يعمل بتحويل حسابي مع تنبيه لاختلاف ثبوت الهلال.
- الصوت مرتبط بـ just_audio، مع خدمة تشغيل قابلة للتوسع.
- الإشعارات المحلية والجدولة موجودة كأساس، مع عدم استخدام exact alarms إلا عند الحاجة.
- مستورد حزم المحتوى يتحقق من SHA-256 وبيانات manifest والمصدر والترخيص.
- أقسام الحديث والأذكار والأسماء والمكتبة والصوت والتقويم تقرأ من المحتوى المحلي بدلاً من بيانات تجريبية.
- GitHub Actions للبناء يدوي فقط عبر workflow_dispatch.
- تم تثبيت مجلدات assets المطلوبة حتى لا يفشل pubspec بسبب مجلدات غير موجودة.

## ما يحتاج اختباراً قبل وصفه إنتاجياً
1. تشغيل build_runner وflutter analyze وflutter test.
2. Android build على runner فعلي.
3. iOS build على macOS runner.
4. مقارنة مواقيت الصلاة مع مرجع موثوق عبر مدن وطرق حساب متعددة.
5. اختبار القبلة مع أجهزة وحالات حساس مختلفة ومعايرة.
6. اختبار الإشعارات والجدولة بعد إعادة التشغيل ووضع توفير البطارية.
7. اختبار الصوت بالخلفية وقفل الشاشة وسماعات Bluetooth.
8. اختبار ترقية قاعدة البيانات والهجرة من schema 2.
9. إدخال حزم قرآن/حديث/تفسير/أذكار مرخصة وموثقة فعلياً.
10. مراجعة تراخيص كل بيانات وصوت وكتاب قبل تضمينها.
11. FTS5/فهرسة البحث عند وصول حجم البيانات الكامل.
12. اختبار RTL والعربية على Android وiOS.

## لا يوجد محتوى ديني مختلق
لا تُضاف آيات أو أحاديث أو أدعية أو أحكام فقهية من ذاكرة النموذج. التطبيق يرفض عملياً اعتبار الحزمة موثوقة دون manifest ومصدر وترخيص وتحقق.

## البناء
لا توجد حاجة لتشغيل GitHub Actions بعد كل commit. البناء يبقى يدوياً كما طلب صاحب المشروع.
