# مَدار | MADAR - وثيقة المشروع المرجعية

> هذه الوثيقة هي المرجع التشغيلي للمشروع. عند تعديل قرار أساسي يجب تحديثها بدل الاعتماد على الذاكرة.

## 1. الهوية
- الاسم العربي: مَدار
- الاسم اللاتيني: MADAR
- Package: `com.madar.app`
- المنصات المستهدفة: Android و iOS
- النهج: تطبيق إسلامي عالمي، Premium، Offline-first، مع نظام قوي للمصادر والتحقق.

## 2. المبدأ الأساسي
صحة المحتوى الديني أولوية مطلقة. لا يتم إنشاء نصوص القرآن أو الحديث أو نسبتها إلى العلماء من الذاكرة. كل مادة يجب أن ترتبط بمصدر واضح ومرجع وترخيص وحالة تحقق.

## 4. القرآن

- أوضاع: مصحف، قراءة، دراسة.
- البحث، التفاسير، الترجمات، الكلمات عند توفر مصدر وترخيص مناسب.
- القراء، التشغيل المتواصل، التكرار للحفظ.
- العلامات، الملاحظات، آخر قراءة، الأهداف والختمة.
- التنزيل والعمل دون اتصال.
- إعداد سلوك الفتح: متابعة آخر قراءة/قائمة السور/آخر سورة/صفحة يحددها المستخدم.
- معلومات الآية ومصادرها، مع عدم عرض ادعاءات غير موثقة.
- ربط الآية بالتفسير والترجمة والآيات والأحاديث والموضوعات عندما يكون الربط موثقًا.

## 10. بقية الأقسام
- أسماء الله الحسنى: الاسم والمعنى والشرح والمصدر والبحث والمفضلة والصوت والروابط الموثقة.
- التسبيح: عداد، جلسات، أهداف، استئناف، سجل، إحصاءات دون مبالغة في التلعيب.
- الحج والعمرة: دليل مراحل، الإحرام والمواقيت والمناسك والأدعية والممنوعات والأخطاء الشائعة والخرائط ووضع إرشادي والعمل دون اتصال.
- المكتبة: السيرة، الأنبياء، الصحابة، علوم القرآن والحديث، الفقه، العقيدة، الآداب والتاريخ، مع مصدر وترخيص لكل مادة.
- الصوت: قرآن ومحتوى موثوق، تشغيل خلفي، شاشة القفل، Bluetooth، قوائم، تكرار، سرعة، مؤقت نوم، وتنزيلات اختيارية.
- البحث: موحد ومصنف مع فتح النتيجة في مصدرها وربط ذكي بين الآيات والأحاديث والتفسير والموضوعات.
- المتابعة: الصلاة والقرآن والأذكار والتسبيح والأهداف والإحصاءات.

## 11. التصميم
هوية Premium هادئة وفاخرة، RTL ممتاز، وضع داكن وفاتح، أخضر زمردي عميق، ذهبي دافئ محدود، خلفيات داكنة/عاجية، عمق وشفافية محسوبة، زخارف هندسية إسلامية ثمانية الرؤوس، وأيقونة مبنية على صفحتين مفتوحتين ومدار متداخل يعطي عمقًا ثلاثي الأبعاد. لا يوجد نص قرآني مقروء داخل الشعار.

## 12. التقنية

## 14. المحتوى والترخيص
- كل Dataset يسجل: المصدر، الإصدار، تاريخ الجمع، الترخيص، شروط الاستخدام، checksum عند الإمكان، وحالة التحقق.
- نص القرآن يحتاج احترام شروط المصدر. مثال: Tanzil يطلب نسب المصدر وعدم تغيير النص، لذلك لا يجوز تطبيع النص الأصلي بطريقة تغيره. يجب حفظ النسخة الأصلية كما هي، ويمكن إنشاء فهارس بحث منفصلة لا تُعرض كنص بديل.
- لا نستخدم Dataset يمنع الاستخدام التجاري إذا كان مستقبل المنتج قد يحتاج نموذجًا تجاريًا، إلا بقرار وترخيص واضحين.
- لا نضم أي صوت/ترجمة/كتاب محمي بحقوق دون ترخيص يسمح بذلك.
- سيتم إنشاء ATTRIBUTION/NOTICE لكل مصدر خارجي مستخدم.

## 16. الصلاحيات
- الموقع: للصلاة والقبلة عند تفعيل الموقع التلقائي.
- الإشعارات: للأذان والتذكيرات والأحداث.
- المنبهات الدقيقة: فقط إذا أثبت التنفيذ حاجتها وكان النظام يسمح بها.
- الملفات: بأضيق صلاحية لازمة.

كل صلاحية يجب أن يكون لها سبب واضح للمستخدم وألا تستخدم دون حاجة.

## 17. أقل أنظمة التشغيل
سيتم اختيار أقل إصدار تدعمه Flutter والمكتبات الأساسية والميزات المطلوبة فعليًا، وليس اختيار رقم مرتفع بلا سبب. في وقت التأسيس تشير وثائق Flutter الحالية إلى دعم Android 24+ وiOS 15+، لكن يجب تثبيت الإصدارات الفعلية للمشروع والتحقق من كل dependency قبل اعتماد الحد النهائي.

## 18. البناء
GitHub Actions لا تعمل عند Push. جميع Builds ستكون manual عبر workflow_dispatch لتقليل استهلاك الحصة. سيطلب من المستخدم تشغيل البناء يدويًا عندما يصبح البناء مناسبًا للاختبار.
